## Stage 4 Addendum

- 当前已补上按累计消除固定行数触发的第二次 3 选 1 最小版本。
- 当前 Rogue 模式已经具备“开局前第一次选择 + 局内第二次选择”的最小实验链路。
- 更复杂的多轮局内选择、局间成长和经济系统继续留到后续阶段。

## Stage 4 Visibility Addendum

- 当前 Rogue 模式 HUD 已能清晰显示本局已选强化、重复叠加次数，以及一次出生保护的剩余次数。
- 经典模式继续保持原有 HUD，不承接 Rogue 专属结果信息。

## Stage 4 Milestone Addendum

- 当前 Rogue 原型已形成第一轮最小实验链路：经典 / Rogue 双入口、开局前第一次选择、局内第二次选择、Hard Drop 奖励、消行奖励、一次出生保护，以及 HUD 结果可见性。
- 当前建议先把这条实验链路作为一轮里程碑收口，再决定下一轮是扩选择轮次、扩强化池，还是补最小局间成长壳层。
- 当前仍未做但不建议继续塞进这一轮的内容：第三次选择、复杂成长系统、更多 Rogue 强化种类、大规模 HUD / UI 改造。

## Rogue Third Choice Addendum

- 当前 Rogue 模式已补上第三次固定触发的 3 选 1，继续采用低侵入、易验证的单局强化路线。
- 当前第三次选择仍复用 Hard Drop 奖励、消行奖励、一次出生保护三种强化，不扩新强化池。

## Rogue Choice Config Addendum

- 当前 Rogue 模式已把选择轮次与触发阈值集中整理为统一配置。
- 第一轮选择在开局前固定触发；第二轮选择在累计消除 2 行后触发；第三轮选择在累计消除 4 行后触发。
- 后续如果继续扩展更多轮次，建议继续沿用这套集中配置方式，而不是把阈值散落在流程逻辑里。

## Rogue Second Milestone Addendum

- 当前 Rogue 原型已经完成第二轮扩展：在第一轮实验链路基础上，补上局内第二次选择、局内第三次固定触发选择，以及轮次 / 阈值集中配置。
- 当前建议先把这轮扩展作为第二轮实验里程碑收口，再决定下一轮是继续扩选择轮次、扩强化池，还是补最小局间成长壳层。
- 当前仍未做但不建议继续塞进这一轮的内容：第四次选择、更多强化种类、复杂成长系统、大规模 Rogue HUD / UI 改造。

## Rogue Meta Shell Addendum

- 当前 Rogue 原型已补上一个最小局间成长壳层：上一局最后一次获得的强化，会作为下一局 Rogue 的额外起始奖励。
- 这层壳子只作用于 Rogue 模式，用来提供跨局延续感，不引入货币、商店或复杂成长系统。
- 经典模式保持原有规则与体验，不承接任何局间成长结果。

## Rogue Meta Rule Addendum

- 当前最小局间成长壳层的规则边界已经明确：它只在 Rogue 模式中生效，只服务于 Rogue 重开闭环，不是永久存档。
- 当前只允许保留一个待带入奖励；当一局结束时，会记录本局最后一次获得的强化，作为下一局 Rogue 的唯一额外起始奖励。
- 这项待带入奖励会在下一局 Rogue 开始时被消费；如果切到经典模式，则会被清空，不会污染经典模式。

## Rogue Third Milestone Addendum

- 当前 Rogue 原型已在前两轮实验链路基础上，补上最小局间成长壳层与局间承接规则清晰化。
- 当前建议先把这条 Rogue 第三轮扩展链路作为第三里程碑收口，再决定下一轮是继续扩选择轮次、扩强化池，还是补更明确的局间成长方向。
- 当前仍未做但不建议继续塞进这一轮的内容：第四次选择、新的强化效果、永久存档、货币系统、大规模 Rogue HUD / UI 改造。

## Rogue Prototype Assessment Addendum

- 当前 Rogue 原型已从“边界预研”推进到“可试玩、可评估方向”的状态。
- 从玩法完整度看：当前已具备经典主循环、三轮固定强化选择、低侵入强化效果与最小局间承接。
- 从实验价值看：当前已经足够支持试玩并评估“选择轮次 + 强化叠加 + 跨局延续感”是否值得继续扩展。
- 从继续扩展风险看：此时同时增加更多强化、更多轮次和更重的局间系统，容易让原型失去清晰边界。
- 当前最推荐的下一步不是继续堆功能，而是先做一轮试玩 / 复盘整理，再决定下一轮 Rogue 扩展方向。

## Rogue Playtest Blocker Fix Addendum

- 当前已优先修补一批阻塞试玩的问题：Rogue 选择触发流程更安全、一次出生保护更有实际帮助、并补上暂停 / 中途重开 / 返回主菜单。
- 当前 Rogue 选择会在锁定结算后、下一块生成前出现，避免在消行奖励结算后把流程卡在不清楚的中间状态。
- 当前一次出生保护会清理整块出生区，而不是只清当前重叠格，因此更容易真正挽救一次失败边缘局面。
- 当前玩家已可在运行中暂停、直接重开或返回主菜单，这一批能力同时适用于经典模式与 Rogue 模式。
## Playtest Feel And UI Fix Addendum

- 当前已补上最小可用的左右长按连续移动，用于改善经典模式与 Rogue 模式的基础手感。
- 当前已对 Next / Hold 预览区做最小宽度稳定化处理，优先减少 Hold 后的界面回流与抖动。
- 这批修复只解决试玩中的手感与 UI 正确性问题，不改变经典模式或 Rogue 模式的核心规则结论。
## Playtest Feedback Fix Addendum

- 当前已补上最小可用的声音反馈：锁定、消行、Hard Drop、游戏结束、重新开始在没有正式资源时仍会有可感知提示音。
- 当前已补上最小可用的消行闪烁反馈，用于帮助玩家确认清行结果。
- 这批反馈增强只服务于试玩感知，不改变经典模式与 Rogue 模式的核心规则结论。
## HUD Focus Conflict Fix Addendum

- 当前已修复游戏进行中的 HUD 焦点误响应：正常游玩时，底部控制按钮不会再跟随方向键获得焦点，也不会再被 Space 误触发。
- 当前只有在暂停、游戏结束或 Rogue 3 选 1 面板打开时，相关按钮才会重新参与键盘焦点与确认输入。
## HUD Layout Stability Addendum

- 当前已对右侧 HUD 做一轮信息架构整理，重点目标是让模式摘要、Rogue 状态、选择提示与系统说明更容易第一眼读懂。
- 当前已通过固定关键区块的最小高度，优先降低 Hold / Next、Rogue 状态与说明文字引发的布局回流。
- 当前 Rogue 选择区在 Rogue 模式下会固定保留位置，不再通过整块出现 / 消失来打乱侧栏布局。
## HUD Product Layer Addendum

- 当前 HUD 已开始从“右侧长文字说明栏”转向“精简常驻 HUD”。
- 当前优先保留玩家长期需要的信息：模式摘要、当前状态、分数 / 等级、预览区、Rogue 摘要、简短操作提示与关键系统状态。
- 当前已将更偏开发期的长说明、内部流程提示和维护性描述降级处理，避免把当前桌面侧栏形态误当成未来 Web / 安卓 / Windows 的正式产品形态。
## Cross-Platform HUD Structure Addendum

- 当前 HUD 已开始向 Web / 安卓 / Windows 三端共用的最小结构靠拢：主界面不再承担大段说明文字，而是优先保留高频信息。
- 当前约定的常驻区块：模式摘要、当前状态、分数 / 等级、Next / Hold、Rogue 摘要（仅 Rogue 模式）。
- 当前约定的按需区块：Rogue 选择区、暂停 / 游戏结束时的提示、关键系统状态；规则说明与详细帮助应逐步转入暂停菜单、帮助页或二级面板。
## Responsive HUD And Help Entry Addendum

- 当前已为游戏主布局补上最小可用的响应式兜底：在较小窗口下，整体内容可通过滚动访问，避免直接溢出。
- 当前已增加 Help 二级入口，用来承接详细操作说明与模式说明；主 HUD 继续只保留高频信息。
- 这一步是结构收敛，不是完整多平台适配，但已经开始朝 Web / 安卓 / Windows 都能成立的展示方式靠近。
## Prototype Freeze Addendum

- 当前版本已达到可试玩原型版的冻结条件：玩法闭环、Rogue 原型链路、关键试玩修复、最小反馈、最小跨平台 HUD 收敛已经形成稳定组合。
- 当前更适合作为下一阶段主线的方向是“性能 / 稳定性整理”，而不是立刻继续扩 Rogue 或直接做完整多端正式适配。
- 原因是：继续扩功能会放大变动面，而直接做多端适配会把当前原型问题复制到更多端；先做稳定性整理更有利于把原型沉淀成可靠基线。
## Stability Pass Addendum

- 当前已先处理一批低风险稳定性问题：输入残留、Rogue 选择 / Help / 暂停之间的焦点与状态切换边界更明确。
- 当前仍值得优先观察的点包括：Help 是否应该在游戏进行中自动暂停、小窗口滚动体验是否足够自然、以及是否需要引入更多回归验证脚本来覆盖状态切换边界。
## Stability Recheck Addendum

- 当前已把 Help 面板收敛为一个受控覆盖层：打开时暂停主循环、阻断游戏输入，关闭后恢复到打开前的暂停状态。
- 当前更值得继续验证的点已经收敛为两类：小窗口滚动兜底是否足够自然，以及是否需要把暂停 / Help / Rogue 选择 / 游戏结束这些状态切换做成更系统的回归检查。
## Cross-Platform Fit Pass Addendum

- 当前已完成多端最小适配的第一步：先把主菜单、游戏主布局和 HUD 预览区整理成在较小窗口下也能成立的基础结构。
- 当前策略仍然是结构层收敛，而不是正式移动端专用 UI；下一步如果继续推进，更适合围绕真实尺寸验证与进一步响应式细化展开。
