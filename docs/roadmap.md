# 项目路线图

## 已完成阶段

1. 第一阶段：最小可玩标准俄罗斯方块
2. 第二阶段：现代标准增强主线
3. 第三阶段：第一轮表现层增强
4. 第四阶段：Rogue 原型三轮实验链路
5. 原型冻结后的试玩修复与基础多端适配

## 当前阶段重点

当前更适合把项目视为：
- 一个已经可试玩的经典模式基线
- 一个已经可评估方向的 Rogue 原型
- 一个正在向 Web / 安卓 / Windows 共用 HUD 结构收敛的原型界面

## 当前多端适配最小约定

- 主菜单：
  - `>= 480px` 进入舒适区
  - `360px - 479px` 依赖滚动访问
- 游戏布局：
  - `>= 920px` 左右布局
  - `< 920px` 上下堆叠
- HUD：
  - 跟随 `< 920px` 进入紧凑表达
  - 常驻只保留高频信息
  - 长说明进入 Help 面板

## 目标尺寸清单

### Web 小窗口
- 参考尺寸：`360 x 640`
- 当前状态：可用
- 当前兜底：滚动菜单、上下堆叠、紧凑 HUD、Help 承接长说明
- 后续优先项：更细的间距与字号断点

### 安卓竖屏
- 参考尺寸：`393 x 852`、`412 x 915`
- 当前状态：结构成立，但仍偏桌面继承布局
- 当前兜底：上下堆叠、紧凑 HUD、Help 面板
- 后续优先项：触控区与竖屏优先布局

### Windows 常见窗口
- 参考尺寸：`960 x 640`、`1024 x 768`、`1280 x 720`
- 当前状态：可用
- 当前兜底：`920px` 断点切换布局
- 后续优先项：更系统的桌面窗口压缩回归

## 当前最合理的后续方向

- 先继续做多端最小适配验证，而不是直接进入完整安卓专用 UI
- 若原型继续扩展功能，建议仍以“小步、可回退、可验证”为原则
