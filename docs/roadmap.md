# 项目路线图

## 已完成阶段
1. 第一阶段：最小可玩标准俄罗斯方块
2. 第二阶段：现代标准增强主线
3. 第三阶段：第一轮表现层增强
4. 第四阶段：Rogue 原型三轮实验链路
5. 原型冻结后的试玩修复与多端最小适配起步

## 当前项目状态

当前项目已经是一个：

- 可试玩的经典模式基线
- 已保留节点的 Rogue 原型
- 已保留节点的跨平台布局打磨结果
- 已保留节点的真实设备尺寸人工回归结果
- 正在 `feature/touch-input-prep` 上继续做触屏输入准备

## 多端最小适配当前结论

### 断点约定
- 主菜单：
  - `>= 480px`：舒适区
  - `360px - 479px`：可用区
  - `< 360px`：暂不保证
- 游戏界面：
  - `>= 920px`：左右布局
  - `< 920px`：上下堆叠
- HUD / Help：
  - `< 920px`：紧凑表达
  - 详细说明进入 Help

### 固定尺寸截图回归结论
- 主菜单：6 个目标尺寸下均可用。
- 经典模式：`360 x 640`、`393 x 852`、`412 x 915`、`960 x 640` 及以上可用。
- Rogue 模式：`360 x 640`、`393 x 852`、`412 x 915`、`960 x 640` 及以上可用。
- Help 面板：`360 x 640`、`393 x 852`、`412 x 915`、`960 x 640`、`1024 x 768`、`1280 x 720` 当前都已达到首屏可见标题、正文和关闭方式的最低可用线。

## 当前最值得继续收敛的方向

- 优先：触屏输入准备
- 其次：触屏输入与现有键盘输入的职责拆分
- 之后：更完整的移动端输入方案

## 当前触屏输入准备进度

- 已完成第一步：把输入层拆成“动作映射 / 瞬时动作 / 持续状态 / 对外接入口”
- 已完成第二步：补上最小触屏输入桥接层
- 已完成第三步：补上极简触屏控件占位层
- 已完成第四步：收紧占位控件显隐条件与最小交互约定
- 已完成第六步：把占位层收成第一版正式触屏控件原型
- 当前键盘输入已经不再直接等同于游戏动作实现细节
- 当前触屏来源已经可以通过独立桥接层进入动作接口，而不是直接耦合 `_unhandled_input()`
- 当前紧凑布局下，屏幕控件已经能实际调用桥接层，证明触屏来源已能走通动作入口
- 当前第一版正式触屏控件原型已经具备：
  - 主移动按钮分组
  - 次级动作按钮分组
  - 更明确的点击 / 按住行为视觉层级
- 当前触屏占位控件只在紧凑布局里的“可交互游戏态”显示；进入 Help、暂停、Rogue 选择、游戏结束时会自动隐藏并释放持续输入
- 后续如果继续做移动端输入，优先在桥接层之上加触屏 UI 或手势层，而不是再把逻辑塞回键盘输入分支
- 当前第一版正式触屏控件原型的复验结论先保持保守：
  - `393 x 852`：可用
  - `360 x 640`：勉强可用
  - 当前最大的风险点已经收敛为：
    - `393 x 852`：次级动作按钮间距仍偏紧
    - `360 x 640`：底部控件与阅读区仍存在明显空间竞争
- 当前 `360 x 640` 的定点修复策略：
  - 保住主移动按钮的按住高度
  - 继续压缩次级动作区高度、字号和行间距
  - 通过减少控件总高度来降低底部空间冲突
- 当前 `360 x 640` 的次级动作区再小收一次：
  - 继续只压次级动作区，不动主按钮按住手感
  - 通过更小的次级按钮高度、内容边距和底部留白，进一步减轻和阅读区的空间竞争
- 当前 `360 x 640` 的次级动作区微调方向：
  - 让旋转 / 硬降继续作为主要次级动作保持更宽点击面
  - 让暂存 / 暂停退到更小的工具按钮层级
  - 继续只调超窄态，不影响 `393 x 852`
- 当前 `360 x 640` 的再次交互复验结论：
  - 主按钮按住和 Help / 暂停 / Rogue 选择 / 游戏结束后的恢复已基本稳定
  - 但次级动作按钮仍偏紧，当前结论继续保持“勉强可用”

## 当前人工回归摘要

- Web 小窗口（`360 x 640`）：
  - 主菜单、经典模式、Rogue 模式、Help 都已达到可用
  - 但整体仍偏紧，主要依赖超窄紧凑态
- 安卓竖屏（`393 x 852`、`412 x 915`）：
  - 主菜单、经典模式、Rogue 模式、Help 都可用

- Windows 常见窗口（`960 x 640`、`1024 x 768`、`1280 x 720`）：
  - 主菜单、经典模式、Rogue 模式稳定可用
  - `960 x 640` 下 Help 已提升到可用，且首屏正文与关闭方式都能稳定看到
  - `1024 x 768`、`1280 x 720` 下 Help 可用

## 当前分支阶段结论

- `feature/cross-platform-layout-polish` 已经作为“跨平台布局打磨节点”保留。
- `feature/device-size-manual-review` 已经作为“真实设备尺寸人工回归节点”保留。
- 当前工作分支已经切换到 `feature/touch-input-prep`。
- 当前分支只负责：
  - 触屏输入准备
  - 为未来移动端输入做结构承接
  - 不继续扩 Rogue 功能，也不修改经典 / Rogue 核心规则

### 窄宽度 Rogue 信息表达约定
- 摘要与效果分开显示，不再把强化结果和轮次提示混成一大段
- 下一轮提示统一收敛为短句，例如 `下一选：第 2 轮 / 2 行后`
- 生效结果统一收敛为短句，例如 `硬降：+1`、`消行：+1/行`、`保护：1`

### 安卓竖屏紧凑态约定
- 目标优先尺寸：`393 x 852`、`412 x 915`
- 进入条件：`< 920px` 的上下堆叠布局下，同时满足 `<= 430px` 宽度和 `>= 800px` 高度
- 当前收敛策略：
  - 棋盘缩一档显示
  - Playfield 上下留白缩小
  - Next / Hold 缩一档
  - Help 使用更短的竖屏帮助文案
  - `393 x 852` 再进入更窄一档棋盘尺寸，优先保证 HUD 首屏可读性

### 超窄紧凑态约定
- 目标优先尺寸：`360 x 640`
- 进入条件：宽度 `<= 360px`，并处于 `< 920px` 的上下堆叠布局
- 当前收敛策略：
  - 棋盘再缩一档
  - Playfield 最小高度再下调
  - HUD 进入更小的字号 / 间距策略，标题层级略收紧
  - 预览尺寸和帮助文案长度继续保持紧凑
  - 主菜单短文案 + 更明确的按钮点击区
  - Help / 会话按钮最小点击高度提升
- 当前结论：
  - 主菜单、经典模式、Rogue 模式、Help 都已达到最低可用线

### 小尺寸字号 / 间距策略
- 目标优先尺寸：`360 x 640`、`393 x 852`
- 当前约定：
  - `360 x 640`：用更紧的标题字号和更稳的按钮点击区，优先保证“可读、可点、可操作”
  - `393 x 852`：保持比超窄态更舒展一档的正文与区块间距，避免竖屏首屏读起来过挤
- 当前状态：
  - 两档都已进入第一轮字号 / 间距收敛
  - 固定尺寸复验后，两档都继续保持“可用”，且没有发现必须立即继续修改的显示问题
  - 后续如继续细化，更适合围绕字号和点击区做小步打磨，而不是再压主布局结构
