# 项目路线图

## 阶段 0：项目初始化

- 建立 Git 仓库与远程绑定
- 建立 Godot 项目骨架
- 建立基础文档、任务板和开发约定

## 阶段 1：标准俄罗斯方块最小闭环

- 先按 [`docs/stage-1-rules.md`](stage-1-rules.md) 明确规则边界
- 按小步任务拆分实现棋盘、方块、移动、下落、锁定
- 完成消行、失败判定、重新开始的最小闭环
- 只做“最小可玩的标准俄罗斯方块”，不提前扩展高级规则

## 阶段 2：现代标准增强与扩展准备

- 先补 Hard Drop、Next Queue、Hold、等级等更接近现代标准俄罗斯方块的能力
- 再做少量结构整理，例如方块来源接口、规则参数入口、运行结果数据出口
- 本阶段仍然不引入 Rogue 玩法本身，只为未来扩展保留清晰边界

当前状态：
- 现代标准增强主线已完成
- 结构整理支线已完成第一轮最小落地
- 第二阶段当前已达到可收口状态

当前已完成的最小落地：
- 方块来源已抽成独立的 7-bag 提供者
- 规则参数已形成统一读取入口
- 运行结果已形成统一数据出口

当前仍未做的内容：
- 更深一层的模块拆分仍可在后续阶段继续，但不作为第二阶段收口前置条件

## 阶段 3：表现层完善

- 补充 HUD、分数、等级、下一个方块预览
- 优化视觉反馈和音效接口
- 为后续扩展预留清晰边界

当前状态：
- 第一轮表现层增强项已完成
- 已完成 Next / Hold 图形化预览
- 已完成 HUD 分区整理
- 已完成最小可用的音效接口层
- 第三阶段当前已达到“可作为一轮里程碑收口”的状态

当前仍未做但不建议强行塞进本阶段的小项：
- 真实音频资源接入
- 更细的 HUD 视觉样式打磨
- 更多动画反馈或表现层特效
- 更长的 Next 队列图形预览

## 阶段 4：Rogue 扩展边界预研

- 先只做规则与结构规划，不直接实现 Rogue 功能
- 优先寻找可叠加在现有俄罗斯方块主循环上的轻量系统
- 先验证“单局强化、选择、风险收益”这些边界清晰的小切口

当前状态：
- 已完成经典模式与 Rogue 模式的独立入口拆分
- 经典模式保持当前已完成的标准俄罗斯方块规则与体验不变
- Rogue 模式当前只提供独立入口和状态壳子，暂不引入完整 Rogue 玩法
- 当前模式边界已搭好，后续实验项可以从 Rogue 模式入口继续叠加
- 已完成 Rogue 模式开局前的第一批强化入口，当前采用固定的 3 选 1 流程
- 已完成 Rogue 模式差异信息在 HUD 中的最小可见化整理
- 第四阶段当前已达到“可作为一轮实验里程碑收口”的状态

当前建议优先切入的方向：
- 局内随机强化：例如本局 Hard Drop 额外得分、特定方块额外加成、基础掉落节奏修饰
- 特殊规则修饰：例如额外 Hold 次数、单局一次性保护、分数倍率类效果
- 风险与收益选择：例如在固定轮次后从 2 到 3 个强化里选 1 个
- 局间成长的最小壳层：只保留解锁池或起始奖励，不急着做复杂经济系统

当前不建议过早加入的方向：
- 需要直接重写棋盘与碰撞基础规则的系统
- 强依赖地图、战斗、事件树的复杂 Rogue 外层结构
- 会迫使当前 HUD 和结算流程大改的大型 meta 系统
- 很难回退、很难单步验证的永久改造

当前已落地的第一批最小实验项：
- 开局前 3 选 1 入口
- Hard Drop 额外得分
- 消行额外得分
- 一次出生保护

当前暂未实现但故意留空的内容：
- 多轮局内选择
- 完整成长与经济系统
- 更多 Rogue 强化种类
- 更复杂的选择 UI 与局外系统

## 暂不进入的内容

- Rogue 系统
- 道具系统
- 局外成长
- 复杂关卡机制

这些方向会保留在未来规划中，但不会在“标准俄罗斯方块基础阶段”提前展开。
