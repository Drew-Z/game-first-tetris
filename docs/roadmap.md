# 项目路线图

## 已完成阶段
1. 第一阶段：最小可玩标准俄罗斯方块
2. 第二阶段：现代标准增强主线
3. 第三阶段：第一轮表现层增强
4. 第四阶段：Rogue 原型三轮实验链路
5. 原型冻结后的试玩修复与多端最小适配起步

## 当前项目状态

当前项目已经是一个：

- 可试玩的经典模式基线
- 已保留节点的 Rogue 原型
- 正在 `feature/cross-platform-layout-polish` 上继续收敛 Web / 安卓 / Windows 共用结构

## 多端最小适配当前结论

### 断点约定
- 主菜单：
  - `>= 480px`：舒适区
  - `360px - 479px`：可用区
  - `< 360px`：暂不保证
- 游戏界面：
  - `>= 920px`：左右布局
  - `< 920px`：上下堆叠
- HUD / Help：
  - `< 920px`：紧凑表达
  - 详细说明进入 Help

### 固定尺寸截图回归结论
- 主菜单：6 个目标尺寸下均可用。
- 经典模式：`960 x 640` 及以上可用；更窄尺寸为勉强可用。
- Rogue 模式：`960 x 640` 及以上可用；更窄尺寸为勉强可用。
- Help 面板：`360 x 640`、`393 x 852`、`412 x 915`、`960 x 640`、`1024 x 768`、`1280 x 720` 当前都已达到首屏可见标题、正文和关闭方式的最低可用线。

## 当前最值得继续收敛的方向

- 优先：窄宽度下 Rogue 信息进一步压缩
- 其次：固定尺寸截图回归基线固化
- 之后：更真实的设备级手工回归

### 窄宽度 Rogue 信息表达约定
- 摘要与效果分开显示，不再把强化结果和轮次提示混成一大段
- 下一轮提示统一收敛为短句，例如 `下一选：第 2 轮 / 2 行后`
- 生效结果统一收敛为短句，例如 `硬降：+1`、`消行：+1/行`、`保护：1`

## 当前分支职责说明

- `main`：继续承接更稳定的经典主线
- `feature/rogue-prototype`：已保留 Rogue 原型节点，作为后续 Rogue 深化的基线
- `feature/cross-platform-layout-polish`：当前只继续推进跨平台布局与界面结构收敛，不继续扩 Rogue 功能
