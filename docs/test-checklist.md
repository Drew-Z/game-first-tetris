## 阶段 1 当前可验证能力

- 第一阶段核心能力的验证项已全部覆盖
- 当前清单可用于确认“第一阶段最小可玩版已完成”

### 1. 项目可正常打开

- 使用 Godot 打开项目不会报场景或脚本错误
- 进入主场景后应先看到“经典模式 / Rogue 模式”两个入口
- 选择任一模式后可以看到棋盘、活动方块和右侧信息面板
- 右侧 HUD 至少应清楚分出“当前状态”“分数 / 等级”“Next / Hold”“操作 / 状态提示”几个区域

### 18. 模式入口拆分

- 经典模式与 Rogue 模式都可以从主入口明确选择
- 进入经典模式后，当前规则和体验应与此前版本保持一致
- 进入 Rogue 模式后，当前仍应能正常运行主循环，但右侧信息中应明确说明这只是 Rogue 模式壳子
- 模式入口拆分不应破坏 Next Queue、Hold、7-bag、Hard Drop、软降、旋转、消行、计分、等级、游戏结束和重新开始流程

### 19. Rogue 模式第一批强化入口

- 进入 Rogue 模式后，开局前应先出现固定的 3 选 1 选择流程
- 经典模式不应出现该选择流程
- 当前 3 个选项里，应至少包含：
  - Hard Drop 额外得分
  - 消行额外得分
  - 一次出生保护
- 选择 Hard Drop 额外得分后，本局每次 Hard Drop 应额外 +1 分
- 选择消行额外得分后，本局每清除 1 行应额外 +1 分
- 选择一次出生保护后，当出生位置第一次被静态格子占用时，应自动清除本次出生格并继续生成；该效果单局只生效一次
- 选择任一 Rogue 选项后，当前主循环仍应保持正常：Next Queue、Hold、7-bag、软降、旋转、锁定、消行、等级、游戏结束、重新开始都不应被破坏
- Rogue 模式运行时，HUD 中应清楚显示“当前处于 Rogue 模式”“本局强化名称”，若选择的是一次出生保护，还应显示当前剩余保护次数
- 经典模式 HUD 中不应出现 Rogue 专属强化信息

### 2. 开局生成活动方块

- 进入游戏后会生成一个活动方块
- 方块出生位置应与右侧面板显示的坐标一致
- 当前活动方块与下一个方块都应来自 7-bag 规则

### 3. 左右移动与左右边界

- 按左方向键，活动方块向左移动一格
- 按右方向键，活动方块向右移动一格
- 活动方块不能移出棋盘左右边界

### 4. 自动下落与到底停止

- 不操作时，活动方块会按固定间隔自动向下移动
- 活动方块触底后会停止继续下落并锁定到棋盘
- 锁定后，棋盘上会保留该方块的静态格子显示
- 锁定后，会立即生成一个新的活动方块
- 新活动方块仍从当前约定的出生位置出现
- 流程可以持续形成“生成 -> 下落 -> 锁定 -> 再生成”循环

### 5. 与静态格子的基础碰撞

- 当棋盘上已有静态格子时，活动方块左右移动不能进入这些格子
- 当活动方块下方已有静态格子时，活动方块会停止继续下落并锁定
- 静态格子会持续保留在棋盘上，后续活动方块需要绕开它们

### 6. 出生位置校验与游戏结束

- 当新活动方块需要生成时，会先检查出生位置是否可用
- 如果出生位置已被静态格子占用，则进入游戏结束状态
- 游戏结束后，不会继续生成新方块
- 游戏结束后，当前不会再响应左右输入
- 游戏结束后，当前不会再继续自动下落

### 7. 重新开始

- 游戏结束后，右侧 `Restart` 按钮可用
- 点击 `Restart` 后，棋盘静态格子会被清空
- 点击 `Restart` 后，会重新生成新的活动方块
- 点击 `Restart` 后，左右移动、自动下落、锁定、继续生成和游戏结束流程都会恢复正常

### 8. 消行

- 当某一整行被静态格子填满时，该行会被清除
- 消除后，该行上方已有静态格子会整体下移
- 消行发生在活动方块锁定并写回棋盘之后
- 消行后，后续活动方块生成、下落、碰撞和游戏结束流程仍保持正常

### 9. 基础计分

- 成功消行后，右侧 UI 分数会增加
- 当前采用最简单规则：每清除 1 行，加 1 分
- 重新开始后，分数会重置为 0
- 游戏结束时，右侧 UI 仍能看到当前分数

### 10. 等级与下落速度成长

- 当前等级会显示在右侧信息面板中
- 当前按“累计消除 5 行升 1 级”的最小规则升级
- 等级提升后，自动下落速度会明显加快
- 点击 `Restart` 后，等级会重置为 1，自动下落速度也会恢复初始状态

### 11. 软降

- 按住下方向键时，活动方块向下移动速度明显快于正常自动下落
- 软降仍然遵守底边限制
- 软降仍然遵守与静态格子的碰撞规则
- 软降不会跳过锁定、继续生成、消行、计分和游戏结束流程

### 12. 基础旋转合法性判断

- 按上方向键时，当前活动方块会尝试顺时针旋转到下一个旋转状态
- 如果旋转后的形状超出棋盘边界，本次旋转无效，活动方块保持原状
- 如果旋转后的形状会与静态格子重叠，本次旋转无效，活动方块保持原状
- 如果旋转成功，右侧面板中的旋转状态会更新
- 旋转不会破坏已有的下落、锁定、消行、计分、游戏结束和重新开始流程

### 13. Hard Drop

- 按 `Space` 触发 `hard_drop` 时，当前活动方块会直接落到当前合法的最低位置
- Hard Drop 仍然遵守底边限制与静态格子碰撞规则
- Hard Drop 完成后，当前活动方块会立即进入锁定流程
- Hard Drop 后仍会正确衔接消行、计分、继续生成、游戏结束和重新开始流程

### 14. Next Queue

- 当前活动方块生成后，右侧信息面板会显示“下一个”方块类型
- Next 预览面板会图形化显示当前下一个方块的形状
- 当前活动方块锁定后，刚才显示的“下一个”方块会成为新的活动方块
- 新的活动方块生成后，系统会继续补出下一个方块类型
- Next Queue 不会破坏 Hard Drop、软降、旋转、消行、计分、游戏结束和重新开始流程

### 15. 7-bag 方块生成

- 连续取出 7 个新方块时，应该能覆盖 `I O T S Z J L` 各一次
- 一个 bag 用尽后，系统会重新洗牌并补充新的 7 个方块
- 当前活动方块、Next Queue 和 Hold 都应与同一套 7-bag 方块来源规则衔接正常

### 16. Hold

- 按 `C` 触发 `hold` 时，当前活动方块可以进入 Hold 槽
- Hold 预览面板会图形化显示当前 Hold 槽里的方块形状
- 如果 Hold 槽原本为空，则当前活动方块会被存入 Hold，并立即换出下一块
- 如果 Hold 槽中已有方块，则会与当前活动方块交换
- 同一个活动方块在锁定前只能 Hold 一次，右侧信息会显示当前 Hold 是否还能使用
- Hold 不会破坏 Next Queue、Hard Drop、软降、旋转、消行、计分、游戏结束和重新开始流程

### 17. 音效接口

- 当前项目已为 `锁定`、`消行`、`Hard Drop`、`游戏结束`、`重新开始` 预留独立音效触发入口
- 在尚未配置正式音频资源时，上述流程执行不应报错
- 后续接入音频资源时，应优先复用当前音效接口层，而不是把播放逻辑直接写进规则判断
