# 测试清单

## 基础运行
- 项目可正常打开
- 经典模式可进入并正常游玩
- Rogue 模式可进入并正常游玩
- Godot 无头运行不报 Unicode 解析错误

## 经典模式
- 方块生成、移动、旋转、软降、Hard Drop 正常
- Hold 正常
- 锁定、消行、计分、等级正常
- 暂停 / 重开 / 返回主菜单正常

## Rogue 模式
- 开局前第一次 `3 选 1` 正常
- 局内第二次选择在累计消除 `2` 行后触发
- 局内第三次选择在累计消除 `4` 行后触发
- Hard Drop 奖励、消行奖励、一次出生保护正常
- 局间带入只在 Rogue 的 Restart 闭环中生效
- Rogue HUD 可正确显示已选强化、叠加次数、剩余保护次数

## HUD / Help
- 正常游戏中，HUD 按钮不会误吃方向键、`Space`、`C`
- Help 打开时会暂停主循环并阻断方块控制输入
- Help 关闭后会恢复到打开前的暂停状态
- 长说明只在 Help 中出现，不回到主 HUD
- 窄宽度下 Rogue 信息区仍能区分“摘要层”和“效果层”
- 窄宽度下 Rogue 下一轮提示应使用短句，不出现长段机制说明
- 窄宽度下 Rogue 生效结果应优先显示短标签和值

## 输入结构
- 键盘输入仍可正常触发左移、右移、软降、旋转、Hard Drop、Hold、暂停
- 左移 / 右移 / 软降应按“持续状态”工作
- 旋转 / Hard Drop / Hold / 暂停应按“瞬时动作”工作
- 输入被阻断时（暂停 / Help / Rogue 选择 / 游戏结束），持续状态不应残留到后续主循环
- 后续触屏输入应优先复用现有动作接口，而不是再直接耦合 `_unhandled_input()`
- `TouchInputBridge.tap_action(...)` 应能触发瞬时动作
- `TouchInputBridge.set_touch_action_pressed(...)` 应能驱动持续状态
- 键盘与触屏来源并存时，一个来源松手不应直接清掉另一个来源仍在保持的持续状态
- 紧凑布局下应能看到 `TouchControls` 占位控件层
- `TouchControls` 的左移 / 右移 / 软降按钮应能驱动持续状态
- `TouchControls` 的旋转 / Hard Drop / Hold / 暂停按钮应能触发瞬时动作

## 固定尺寸截图回归

### 目标尺寸
- Web 小窗口：`360 x 640`
- 安卓竖屏：`393 x 852`
- 安卓竖屏：`412 x 915`
- Windows：`960 x 640`
- Windows：`1024 x 768`
- Windows：`1280 x 720`

### 每个尺寸固定检查 4 个画面
- 主菜单
- 游戏中经典模式
- 游戏中 Rogue 模式
- Help 面板

### 当前回归结论
- 主菜单：6 个尺寸下均可用
- 经典模式：6 个目标尺寸下均可用
- Rogue 模式：6 个目标尺寸下均可用
- Help 面板：6 个目标尺寸下均已达到最低可用线

### Help 首屏可见性额外判断
- 打开后首屏就能看到帮助标题
- 打开后首屏就能看到有效正文，而不是只看到棋盘或系统区
- 打开后首屏就能看到明确关闭方式（`Close Help` 或 `Esc`）
- 主要帮助信息不需要先大量滚动才能理解

### 判断标准
- 没有乱码
- 没有明显截断
- 没有明显重叠
- 没有关键按钮不可访问
- 当前布局方向符合断点约定

### 安卓竖屏额外判断
- `393 x 852`、`412 x 915` 下，棋盘应缩一档显示，不再把 HUD 整体压到首屏之外
- `393 x 852` 下，经典模式和 Rogue 模式首屏都应能看到预览区开头
- `393 x 852`、`412 x 915` 下，Rogue 信息区应保持“摘要层 + 效果层”分层
- `393 x 852`、`412 x 915` 下，Help 应使用更短的竖屏帮助文案

### 极窄尺寸额外判断
- `360 x 640` 下，应进入“超窄紧凑态”
- `360 x 640` 下，经典模式首屏应至少能看到“当前状态”区
- `360 x 640` 下，Rogue 模式首屏应至少能看到模式摘要和“当前状态”区
- `360 x 640` 下，Help 首屏仍应能直接读到帮助正文和关闭方式
- `360 x 640` 下，主菜单主要按钮应具备更明确的点击高度
- `360 x 640` 下，Help / Pause / Main Menu / Restart 按钮应保持易点，不应因为紧凑态缩得过小

### 小尺寸字号 / 间距额外判断
- `360 x 640` 下，标题字号应明显小于默认态，但正文仍保持可读
- `360 x 640` 下，按钮区与信息区之间不应紧贴到难以分辨
- `393 x 852` 下，标题层级应清楚，不应出现“标题太大、正文太挤”的观感
- `393 x 852` 下，Help、系统按钮和 Rogue 选择按钮应保持稳定点击高度

### 本轮字号 / 间距复验结论
- `360 x 640`：经典模式、Rogue 模式、Help 继续保持可用，且没有出现比上一轮更差的字体或留白问题
- `393 x 852`：经典模式、Rogue 模式、Help 继续保持可用，当前无需继续为字号 / 间距单独改代码
- `412 x 915`：顺带复验未发现回退
