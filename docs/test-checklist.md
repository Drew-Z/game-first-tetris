## Rogue 第二里程碑结论

- 下一轮扩展前，建议先以现有清单完成一次完整回归验证。

## Rogue 局间成长壳层补充验证

- 只在 Rogue 模式中，游戏结束后应为下一局准备一个额外起始奖励。
- 当前最小规则为：上一局最后一次获得的强化，会成为下一局 Rogue 的额外起始奖励。
- 点击 Restart 进入下一局 Rogue 后，HUD 中应能看到“本局带入”已显示该起始奖励。
- 经典模式不应显示或继承任何局间成长结果。

## Rogue 局间承接规则补充验证

- 当前局间带入只应在 Rogue 模式中生效，经典模式不应显示或继承任何带入结果。
- 当前局间带入只保留一个待带入奖励；新一局结束后记录的结果应覆盖旧的待带入结果。
- 当前待带入奖励只服务于 Rogue 的 Restart 闭环，不要求跨主菜单或永久保留。
- 下一局 Rogue 开始后，待带入奖励应转为“本局带入”，并清空“下一局带入”。
- 切到经典模式后，当前 Rogue 局间带入状态应被清空。

## Rogue 试玩与复盘检查点

- 试玩重点 1：三轮固定触发选择是否让一局内部出现清晰的阶段感。
- 试玩重点 2：Hard Drop 奖励、消行奖励、一次出生保护在单局里是否都能被明显感知。
- 试玩重点 3：最小局间带入是否让下一局开始时有明确的延续感。
- 重点观察：第二轮与第三轮触发时机是否合适；重复选择同一强化是否仍然值得；一次出生保护是否真正挽救了局势；局间带入是否提升了继续玩的意愿。
- 复盘记录：本局选了什么、哪一项强化最有存在感、哪一项最无感、哪一轮选择最关键、结束后是否想立刻再开一局。
- 本轮试玩后优先回答的问题：
  - 三轮固定选择是否已经足够支撑 Rogue 原型节奏？
  - 当前三种强化里，是否存在明显鸡肋或明显过强的项？
  - 局间带入是否真的带来了跨局延续感？
  - 下一轮更值得先扩强化池，还是先继续扩选择轮次？

## 试玩阻塞问题补充验证

- Rogue 模式下，当消行触发局内选择轮次时，选择面板应在锁定结算后稳定出现，不应表现为卡死。
- 选择完成后，新的活动方块应继续正常生成，主循环应恢复。
- 一次出生保护触发时，应清理整块出生区，而不是只清理单个重叠格；触发后应更容易继续当前局面。
- 游戏进行中应可通过 Pause 按钮或 Esc 暂停 / 恢复。
- 游戏进行中应可通过 Restart 直接中途重开。
- 游戏进行中应可通过 Main Menu 返回主菜单。
- 上述流程在经典模式与 Rogue 模式中都应正常工作，但经典模式不应显示 Rogue 专属选择与强化信息。
## 试玩手感与 UI 正确性补充验证

- 按住左方向键时，活动方块应在初始一步之后继续稳定向左连续移动；按住右方向键时同理。
- 长按连续移动在经典模式与 Rogue 模式中都应可用，并继续遵守边界、静态格子碰撞、暂停和局内选择暂停规则。
- 按 C 执行 Hold 后，Next / Hold 预览区域不应再出现明显的画面抖动或布局抖动。
- 暂停、中途重开、返回主菜单在这批修复后仍应保持正常工作。
## 试玩声音反馈与消行特效补充验证

- 锁定、消行、Hard Drop、游戏结束、重新开始都应有最小可感知的声音反馈；即使项目里没有正式音频资源，也不应静默。
- 消行发生时，棋盘中被清掉的行位置应出现一次短暂的整行闪烁反馈。
- 上述反馈在经典模式与 Rogue 模式中都应正常工作，并继续与暂停、中途重开、返回主菜单、Rogue 选择流程兼容。
## HUD 焦点误响应补充验证

- 游戏正常进行时，方向键应只控制方块移动，不应再改变 Resume / Restart / Main Menu 的选中状态。
- 游戏正常进行时，Space 应只触发 Hard Drop，不应再同时触发当前 HUD 中被选中的按钮。
- 游戏正常进行时，C 应只触发 Hold，不应把 HUD 按钮带入焦点响应。
- 只有在暂停、游戏结束或 Rogue 选择面板打开时，相关按钮才应重新允许键盘焦点与确认输入。
## HUD 信息架构与稳定布局补充验证

- Hold / Next 区域在执行 Hold、生成新方块或切换模式时，不应再因为右侧文字行数变化而出现明显布局抖动。
- Rogue 状态区应稳定分为“摘要信息”和“强化效果”两块，信息应比之前更容易快速读懂。
- Rogue 选择区在 Rogue 模式下应固定占位：未触发选择时显示等待说明，触发 3 选 1 时切换为明确选择提示与按钮。
- 经典模式下不应显示 Rogue 专属状态区与 Rogue 选择区。
## HUD 正式玩家信息分层补充验证

- 当前右侧 HUD 应优先显示正式玩家长期需要的信息，不应再被大段开发期说明占满。
- 经典模式下不应常驻显示 Rogue 专属信息；Rogue 模式下应只显示与当前局真正相关的 Rogue 摘要与选择区。
- 当前状态区不应再显示位置坐标、旋转编号等更偏调试的信息。
- 系统状态区应尽量保持简短，只在暂停、游戏结束、Rogue 强化进行中等关键时刻给出明确提示。
## 三端共用 HUD 结构补充验证

- 主 HUD 应优先只保留高频信息：模式摘要、当前状态、分数 / 等级、Next / Hold，以及 Rogue 模式下的最小摘要。
- 操作提示不应再长期常驻；只有在暂停、游戏结束或 Rogue 选择等需要时才显示。
- 长段规则说明、详细机制解释和开发期说明不应再常驻在主 HUD。
- 经典模式与 Rogue 模式都应仍可正常使用当前 HUD 结构。
## 响应式布局与二级帮助入口补充验证

- 将窗口缩小后，主布局不应直接溢出到不可访问；至少应可通过滚动访问完整内容。
- 主 HUD 不应再重新承载长段说明文字；详细说明应通过 Help 入口查看。
- Help 面板应能显示基础操作说明、主循环说明，以及经典模式 / Rogue 模式的最小区别说明。
- 经典模式与 Rogue 模式都应仍可正常使用当前 HUD 结构与 Help 入口。
## 原型冻结补充验证

- 当前版本应已能完整支撑一次“经典模式可玩 + Rogue 原型可玩”的试玩验证。
- 暂停、中途重开、返回主菜单、声音反馈、消行闪烁、HUD 焦点修复、Help 入口都应保持正常。
- 小窗口下至少应能通过滚动访问完整布局，不应出现主内容完全不可达的情况。
- 原型冻结后，新增工作应优先围绕稳定性整理，而不是继续扩大功能面。
## 稳定性整理补充验证

- 在 Hold、Hard Drop、锁定、返回主菜单之后，不应再残留上一阶段的横向长按移动状态。
- Rogue 选择面板是否打开，应以明确状态为准；不应再因为面板固定占位而误判为“正在选择中”。
- Help 面板显示 / 隐藏时，不应破坏暂停、游戏结束、Rogue 选择的焦点规则。
- 经典模式与 Rogue 模式都应继续正常通过当前状态切换流程。
## Stability Recheck Addendum

- 打开 Help 面板后，主循环应暂停；方向键、Space、C 不应继续作用于当前方块。
- Help 打开时按 Esc，应优先关闭 Help；关闭后应恢复到打开前的暂停状态，而不是额外切换一次暂停。
- 从 Help 打开状态执行 Restart 或返回主菜单，不应残留 Help 状态或焦点状态。
## 多端最小适配补充验证

- 缩小窗口宽度后，游戏主布局应允许棋盘区与侧栏改为上下堆叠，而不是继续横向严重挤压。
